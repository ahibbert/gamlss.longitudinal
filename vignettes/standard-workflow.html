Standard Workflow API, Inference, and Diagnostics

This vignette gives the minimal standard workflow for applied longitudinal analyses with gamlss.longitudinal, highlighting key functions. It is deliberately narrow: get the margin roughly right, choose a reasonable copula / dependence structure, fit the longitudinal model, check the result, then report response-scale answers.

Use this as the default path before moving to the focused guides for replacing a GEE, replacing a random-intercept GLMM, handling non-Gaussian outcomes, missing visits, or time-varying dependence.

Functions Covered

This vignette demonstrates or describes every user-facing function added for the standard adoption workflow.

Data Requirements

Start with one row per subject and visit. The model needs:

  • a response column;
  • a subject identifier;
  • a visit, time, or occasion variable;
  • scientific predictors for the margin;
  • optional predictors for scale, shape, or dependence.

The small simulated dataset below has the required structure and can be used to run the workflow chunks.

set.seed(1)

n_subjects <- 40
visit_times <- 0:3
dat <- expand.grid(
  subject = seq_len(n_subjects),
  time = visit_times
)

subject_covariates <- data.frame(
  subject = seq_len(n_subjects),
  treatment = rep(c("control", "active"), length.out = n_subjects),
  age_scaled = as.numeric(scale(rnorm(n_subjects, mean = 55, sd = 10))),
  subject_shift = rnorm(n_subjects, sd = 0.35)
)

dat <- merge(dat, subject_covariates, by = "subject")
dat$treatment <- factor(dat$treatment)
dat$true_mu <- exp(1.6 + 0.35 * (dat$treatment == "active") + 0.12 * dat$time + dat$subject_shift)
dat$true_sigma <- exp(-0.5 + 0.08 * dat$time)
dat$response <- rgamma(
  nrow(dat),
  shape = 1 / dat$true_sigma^2,
  scale = dat$true_mu * dat$true_sigma^2
)
dat$subject_shift <- NULL
str(dat)
table(dat$subject)
table(dat$time)

Unbalanced panels and missing visits are allowed, but the missingness mechanism still needs to be part of the scientific judgement. See vignette("missing-visits", package = "gamlss.longitudinal") for that case.

Step 1: Screen The Margin

Screen the response distribution before fitting the longitudinal dependence model. This is not the final model; it is a fast way to avoid starting with an obviously poor family.

margin_screen <- screen_margin(
  dat,
  response_var = "response",
  families = c("NO", "GA", "LOGNO", "PO")
)

margin_screen

Use the screen as a shortlist, then choose a family that makes scientific sense. For example, positive skewed outcomes often start with GA() or LOGNO(), counts with PO(), and approximately symmetric continuous outcomes with NO().

margin_dist <- gamlss.dist::GA(mu.link = "log", sigma.link = "log")

Step 2: Screen The Copula

Use select_copula() to compare dependence families. The easiest route is to fit a lightweight marginal model using the screened family, convert the responses to pseudo-observations, and pass those values directly to select_copula().

margin_fit <- gamlss::gamlss(
  response ~ treatment + time + age_scaled,
  sigma.fo = ~ treatment + time,
  family = margin_dist,
  data = dat,
  trace = FALSE
)

dat$u <- gamlss.dist::pGA(
  q = dat$response,
  mu = fitted(margin_fit, what = "mu"),
  sigma = fitted(margin_fit, what = "sigma")
)
dat$u <- pmin(pmax(dat$u, 1e-6), 1 - 1e-6)
copula_screen <- select_copula(
  data = dat,
  u_var = "u",
  subject_var = "subject",
  time_var = "time",
  families = c("N", "C", "F", "G", "J", "t")
)

copula_screen
copula_dist <- attr(copula_screen, "selected")

The selected family is a starting point, not a guarantee. Dependence diagnostics after the full fit matter more than the screen.

Step 3: Fit The Longitudinal Model

Put the main scientific effects in mu.formula. Add sigma.formula when spread changes across time, treatment, or baseline covariates. Add theta.formula when dependence plausibly changes over follow-up or with subject-level predictors.

fit <- fit_longitudinal(
  dataset = dat,
  margin_dist = margin_dist,
  copula_dist = copula_dist,
  time_var = "time",
  subject_var = "subject",
  mu.formula = response ~ treatment + time + s(age_scaled, bs = "ps"),
  sigma.formula = ~ treatment + time,
  theta.formula = ~ time,
  compute_vcov = FALSE,
  run_checks = TRUE
)

For final reporting, request variance-covariance output on the final model:

summary(fit, include_vcov = TRUE)
confint(fit)
wald_test(fit, terms = "mu.treatment")
likelihood_compare(fit_reduced, fit)

boot <- bootstrap_inference(fit, R = 200, terms = "mu.treatment")
boot

See vignette("inference-uncertainty", package = "gamlss.longitudinal") for the reporting language around Hessian, numerical-Hessian, delta-method, and simulation-based uncertainty. See vignette("diagnostics-decisions", package = "gamlss.longitudinal") for the decision language around marginal, tail, dependence, and inference warnings.

Step 4: Check Before Interpreting

Run check_model() before interpreting coefficients or predictions.

check <- check_model(fit, include_vcov = TRUE)
check
check$warnings
check$recommendation
plot(check)
copula_time_summary(fit)

Treat the output as a decision aid:

  • marginal warnings mean the response family or parameter formulas need work;
  • tail warnings mean quantile or probability claims are not yet trustworthy;
  • residual-dependence warnings mean the copula family or theta.formula may be underfitting longitudinal association;
  • inference warnings mean intervals should be reported as approximate or the model should be simplified.

Only move to primary-model reporting once the diagnostics match the intended estimand.

Step 5: Report Applied Answers

Prefer response-scale summaries over raw coefficient tables when communicating with applied collaborators.

predict(
  fit,
  newdata = dat,
  type = "response",
  se.fit = TRUE,
  interval = "confidence"
)

predict(
  fit,
  newdata = dat,
  type = "parameters"
)

predict(
  fit,
  newdata = dat,
  type = "quantile",
  probs = c(0.1, 0.5, 0.9)
)

predict(
  fit,
  newdata = dat,
  type = "cdf",
  q = 10
)

predict(
  fit,
  newdata = dat,
  type = "density",
  y = 10
)

predict(
  fit,
  newdata = dat,
  type = "probability",
  q = 10,
  direction = "above"
)

marginal_effects(
  fit,
  newdata = dat,
  variable = "treatment",
  parameter = "mu",
  se.fit = TRUE
)

effects(
  fit,
  newdata = dat,
  variable = "treatment",
  parameter = "mu",
  se.fit = TRUE
)

If the target is a trajectory or a dependence-sensitive event, simulate from the fitted model:

sim_marginal <- simulate(fit, nsim = 100, type = "marginal", seed = 1)
sim_copula <- simulate(fit, nsim = 100, type = "copula", seed = 1)

Step 6: Compare Against Familiar Models

A replacement claim needs a sensitivity comparison. Use the built-in benchmark scaffold for a quick check, then the adoption benchmark runner for repeated simulation evidence.

benchmark_standard_models(
  data = dat,
  formula = response ~ treatment + time + age_scaled,
  subject_var = "subject",
  family = "gaussian",
  comparators = c("gee", "glmm", "gam")
)

For repeated evidence:

bench <- run_adoption_benchmarks(
  scenarios = "gaussian_heteroskedastic",
  reps = 25,

write_benchmark_report(bench)

Minimal Reporting Checklist

A complete applied report should state:

  1. why a distributional longitudinal model was needed;
  2. the margin family and copula family;
  3. which predictors entered mu, sigma, and theta;
  4. the main check_model() decisions;
  5. the inference route used for intervals;
  6. the response-scale estimands reported;
  7. the GEE, GLMM, or GAM sensitivity result.

If the report only needs a marginal mean and the diagnostics do not suggest distributional or dependence problems, a GEE may still be the better primary model. The goal is not to replace familiar models everywhere; it is to make the GAMLSS-copula workflow the standard when margins, tails, heteroskedasticity, or dependence are part of the answer.
