# Fit-scaling evidence

This public-derived bundle was regenerated by `paper/R/10-fit-scaling.R` from a
target-integrated full-profile run in a clean worktree on 2026-09-02 at Git SHA
`16f80ad7f534c0793544b9a07326d14d3d968fc3`. It contains no private data. The
eight excluded warm-up fits and 54 measured fits are all retained in the
attempt-level source; every measured fit converged and all eight cells met the
registered numerical precision and completeness gate. Independent promotion
validation reconstructed every summary and contrast from the exact attempts
before this bundle became the approved public source for the `paper` profile.

- `scenarios.csv` registers the continuous Normal/Gaussian and discrete
  NBI/Clayton one-factor-at-a-time designs.
- `attempts.csv` retains every fit attempt, including one explicitly excluded
  warm-up per scenario, convergence, warnings, named failure states, stable
  scenario-keyed seeds, global execution order, separate simulation/setup/fit
  timings, and checkpoint/session contract fingerprints. `elapsed_sec` and
  `fit_elapsed_sec` are identical fit-only timings; simulation and setup are
  excluded from the scaling metric.
- `summary.csv` reports median/IQR fit-only elapsed time, bootstrap MCSE and intervals,
  attempted/converged/retained/failed counts, and whether the registered
  relative-MCSE stopping target was reached.
- `contrasts.csv` reports differences and runtime ratios against each
  family-specific base case, with bootstrap MCSE and 95% intervals.
- `hardware.csv` records the CPU model, platform, R and dependency versions,
  Git state, logical cores, workers, execution context, and timing unit.

Checkpoint schema 3 binds reuse to the exact registered design, fitting and
precision configuration, implementation fingerprint, dependency versions,
seed scheme, base seed, Git state, R/platform/OS, CPU, and execution context.
The publication gate deterministically recomputes summaries and contrasts from
attempts and reconciles every field using absolute tolerance `1e-10` plus
relative tolerance `1e-8`. It also requires the hardware row to match attempt
session provenance, preventing dirty standalone timings from being relabeled.
The production integration set `settings$target_integrated <- TRUE` and ran the
full profile through the target graph from a clean worktree before the manifest
hashes below were approved.

The measurements support only the registered subject, visit, and smooth-basis
settings. They must not be extrapolated to other families, copulas, optimizers,
covariance methods, hardware, or substantially larger models.
